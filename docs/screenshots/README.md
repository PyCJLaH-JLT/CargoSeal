# Походження знімків

Фактичні знімки Wokwi та PulseView зроблено під час власних перевірок 13 жовтня 2026. PulseView відкривав .sr з цього CargoSeal, а не з іншого проекту. Для фінальних кадрів прибрано тільки порожню нижню область вікна, яка містила вказівник Codex. Збережено назву програми й файлу, шкали, сигнали та всі потрібні анотації. Повні початкові кадри залишено в Lab02/Work/screenshots; зміст сигналів і значення не редагували.

Фінальні фрагменти знято через CUA browser screenshot ROI із локального перегляду незміненого native кадру. Переглядач масштабував кадр до 1280 px, ROI охоплює верхні 450 px. Кожен остаточний кадр перевірено збільшеним на відсутність mouse/Codex overlay.

PulseView Timing використовує режим any edges. У i2c-clock.sr Data є псевдонімом SCL PB8: інтервали HIGH і LOW по 5 µs, повний T=10 µs. В adc-marker-width.sr та adc-marker-timing.sr Data є псевдонімом ADC_MARK PA4, сигнал не змінено. Width 71.650 µs на .sr20 MHz відрізняється від 71.675 µs у вихідному VCD на 25 ns через ресемплювання. Значення Frequency для pulse width є оберненою шириною, а не частотою опитування ADC.

На period view Timing49.926 ms є інтервалом LOW до наступного HIGH; додавання ширини0.071675 ms дає49.997675 ms повного циклу. Average≈24 ms враховує обидва фронти. Медіану періоду49.99745 ms обчислено по всьому VCD у measurements.json.

UART snapshot показує uart-read-prefix.sr, читабельний початок READ_IMU у hex. Повний текст міститься у uart-read-imu.annotations.txt. I²C snapshot містить masterNACK останнього byte, адреснийNACK показано окремо. Знімки Wokwi є справжнім UART/стендом, не складеним макетом.
