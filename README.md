# CargoSeal

Контроль контейнера з експонатом. Власник: Літвінов Руслан Олексійович, ІО-36.

Середовище: Ubuntu 24.04, Docker, STM32 HAL, Wokwi. Плата симуляції Nucleo-C031C6, фізичного обладнання немає.

## Що підготовлено

ЛР1 використовує незмінений HAL-шаблон. USART2 на PA2/PA3 передає `STM32C031C6 ready` та `tick N`, LED PA5 перемикається приблизно щосекунди. Це поведінка за кодом, її запуск у Wokwi ще не підтверджено. Датчиків у схемі немає; I²C1 ініціалізований на PB8/PB9, але не читає жодного пристрою. ADC та керування режимами ще не реалізовані.

- [PRD](docs/PRD.md): користувачі, два режими, 14 перевірюваних вимог та приймальні тести.
- [Компоненти](docs/hardware-components.md): фактична конфігурація, майбутні піни, альтернативи й джерела ST/Wokwi.
- [План ЛР1/ЛР2](docs/milestones.md).
- [Перевірки збірки](docs/verification/README.md): справжні логи, SHA256 і межі відтворюваності.

## Збірка

Потрібні Docker та `make` на хості. З кореня цієї копії:

```sh
docker --version
docker info
make clean
make build
ls -lh firmware/build/firmware.elf firmware/build/firmware.hex firmware/build/firmware.bin
```

`make build` збирає Docker-образ, запускає ARM GCC у контейнері та створює ELF, HEX і BIN. `make clean` видаляє лише `firmware/build`. Контейнер запускається з UID/GID поточного користувача. Результати збірки виключені з Git, їх потрібно створити перед симуляцією. Параметри тулчейну містяться в `docker/Dockerfile`, ціль Cortex-M0+ у `firmware/Makefile`.

## Підтверджені перевірки

2026-10-04 виконано дві чисті Docker-збірки на Mac і одну на Ubuntu 24.04. У двох Mac-збірках усі SHA256 ELF/HEX/BIN однакові. Між Mac та Ubuntu HEX і BIN також однакові. Повні ELF відрізняються лише рядком шляху збірки libgcc у `.debug_str`; усі завантажувані секції та ELF після `--strip-debug` збігаються. Повну побайтову ідентичність початкових ELF між платформами не підтверджено.

Прошивка, `.ioc`, `diagram.json`, `wokwi.toml` і Docker-шаблон збережені без змін. Компіляція не підтверджує реакції UART/LED під час виконання або працездатність майбутніх датчиків.

## Запуск Wokwi

Відкрити цю папку у VS Code з розширенням Wokwi та вже доступною ліцензією. Після збірки відкрити палітру команд і виконати `Wokwi: Start Simulator`. Конфігурація `wokwi.toml` завантажує `firmware/build/firmware.hex` та використовує `.elf` для відлагодження.

Очікуються одне `STM32C031C6 ready`, щонайменше п'ять послідовних `tick` і блимання LED PA5. Номер tick відображає `HAL_GetTick() / 1000`, тому перший може бути нульовим. Повний цикл увімкнення/вимкнення LED займає близько 2 с. При повторному запуску прошивки лічильник починається заново.

Симуляцію не запускали й trial не активували. Реальні докази Wokwi та PDF-звіт залишаються окремими кроками; вони ще не підготовлені.

## Наступний етап

У ЛР2 MPU6050 має реєструвати звичайний рух при перевезенні та окремо удари. У режимі встановленого контейнера рух IMU є приводом для тривоги, PIR позначає активність поруч. LDR через ADC дає непряму ознаку можливого доступу за зміною світла всередині. Режим перемикає оператор, датчики його не визначають.

Спочатку потрібно перевірити кожен інтерфейс, потім переходи режимів, пороги, помилки й одночасні сигнали за PRD. Секундний блокуючий цикл шаблону треба замінити на регулярне опитування. Числові пороги в документах є початковими припущеннями, а не результатами фізичного калібрування.
