# CargoSeal

Контроль контейнера з експонатом. Власник: Літвінов Руслан Олексійович, ІО-36.

Дисципліна: Системне програмування. Середовище: Ubuntu 24.04, Docker, STM32 HAL, Wokwi. Плата симуляції: Nucleo-C031C6, без фізичного обладнання.

## Поточний стан

Прошивка, конфігурація CubeMX і схема Wokwi збережені без змін. У шаблоні є UART2, стартове повідомлення `STM32C031C6 ready`, періодичні `tick` та LED PA5. Датчики ще не додані. Документи визначають майбутню поведінку; симуляція цієї копії поки не підтверджена.

## Документи

- [PRD](docs/PRD.md): користувачі, два режими, 14 вимог та приймальні тести.
- [Компоненти](docs/hardware-components.md): фактичні параметри HAL-шаблону, джерела й майбутня схема.
- [План](docs/milestones.md): кроки ЛР1 та ЛР2.

## План ЛР1

Підготувати PRD та опис компонентів. Перевірити Docker, виконати дві чисті збірки, порівняти ELF/HEX/BIN. Запустити Wokwi, перевірити UART і LED та зберегти власні докази для звіту.

Команди з кореня проєкту:

```sh
make clean
make build
```

У VS Code відкрити цю папку й виконати `Wokwi: Start Simulator` після збірки. `wokwi.toml` посилається на файли у `firmware/build`.

## План ЛР2

PIR через GPIO позначатиме рух поруч лише на стоянці, MPU6050 через I²C вимірюватиме рух та удари, LDR через ADC зміну світла всередині. Режими перевезення та стоянки перемикатимуться явно. Звичайний рух у перевезенні не є тривогою; зміна світла є непрямою ознакою доступу.

Спочатку перевірити кожен компонент окремо, потім одночасне опитування. Пороги й частоти визначити під час вимірювань; підготувати тести нормальних сигналів, меж і помилок читання. Поточний секундний цикл UART/LED не є готовим опитуванням датчиків.
